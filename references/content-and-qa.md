# 내용 설계와 품질 검수

## 메시지 설계

슬라이드별로 주제 제목, Header, 근거, 표현 방식, 원자료 위치, 미확정 사항을 먼저 정한다. Header만 이어 읽고 중복·비약·누락을 고친 뒤 본문을 제작한다.

- 제목은 짧은 명사형으로 주제·분석 영역을 표현한다. 원칙적으로 한 줄이다. 같은 섹션에서 제목을 반복해도 되지만 Header는 페이지별 고유한 메시지여야 한다.
- Header는 가장 중요한 결론·시사점·권고를 1~2문장으로 표현한다. 가능하면 핵심 판단과 그 근거/시사점을 연결한다.
- 범위·절차 설명 자료라면 무엇을 어떻게 수행하는지 요약한다.
- 제목을 다시 풀어 쓰거나 “다음과 같습니다”, “현황을 살펴봅니다” 같은 소개 문구로 채우지 않는다.
- 본문에서 확인되지 않는 주장·수치는 추가하지 않는다. 가정이 필요한 결론에는 핵심 가정을 명시한다.
- 1~2문장과 화면상의 줄 수는 별개다. 고정 Header 영역에 들어가지 않으면 문장을 다듬거나 페이지를 분리한다.
- 본문은 Header의 복사가 아니라 그 근거다. 한 페이지에 하나의 중심 메시지만 둔다.

## 표현 방식 선택

| 정보 관계 | 우선 표현 |
|---|---|
| 속성·차이·장단점 비교 | 비교표·매트릭스 |
| 순서·절차·업무 흐름 | 프로세스·스윔레인 |
| 일정·마일스톤 | 로드맵·타임라인 |
| 원인·문제·영향·대응 | 인과관계도·대응 매핑 |
| 계층·분류·조직 | 트리·계층도 |
| 위험·통제·검토 절차 | 매핑 테이블 |
| 실제 정량 비교·추이·구성 | 적합한 편집형 차트 |
| 대안 평가 | 평가표·근거 있는 매트릭스 |
| 독립된 사례·핵심 요소 | 구조화 카드·사례표 |

실제 관계가 약하면 복잡한 도식을 억지로 만들지 않는다. 독립된 항목을 임의의 단계·순위로 바꾸지 않는다. 반복 개선은 실제 루프가 보이도록 표현한다. 필요하면 주 도식과 보조 표를 조합한다. 사용자에게 매번 표·도식 종류를 선택하게 하지 않는다.

## 사실과 근거

다음 상태를 구분한다.

1. 원고에 제시된 사실
2. 실습용 가상 사례
3. 특정 조건이 성립할 때의 결론
4. 외부 검증이 필요한 제품명·버전·기능·지식 기준일
5. 원문 대사·재계산이 필요한 수치

수치가 충돌하거나 상세 계산이 없으면 값을 임의로 맞추지 않는다. 미확정 수치를 확정형 제목이나 결론에 쓰지 않는다. 필요하면 본문에서 제외하고 필요한 자료·가정·확인 항목을 노트/부록에 남긴다. 중요한 조건부 가정은 노트로만 숨기지 않는다.

회계·세무 등 전문 사례는 적용 기준, 관점, 거래 조건을 먼저 고정한다. 다른 기준이나 사례에 결과를 일반화하지 않는다. 계약·청구·입금·수익 등 서로 다른 개념을 합치지 않는다. 제품 기능 시연과 상용 서비스 전체의 품질·보안·데이터 범위가 동등하다고 주장하지 않는다.

원고의 반복 설명과 잘못된 단계 번호는 의미를 보존하며 정리한다. 근거 없는 숫자·랭킹·점수·정량 차트·2×2 좌표는 만들지 않는다. 장수를 맞추기 위해 근거와 조건을 삭제하지 않는다.

## 출처와 노트

각 슬라이드의 주요 주장·수치가 어느 원자료에서 왔는지 대응 관계를 남긴다. 문서명과 절·페이지·문단 또는 URL을 식별한다. 원문 페이지를 모르면 문단 순서 등 다른 식별자임을 명시한다.

발표자 노트에는 상세 설명, 원고 발췌, 진행 메모, 적용 조건, 검증 필요사항을 넣을 수 있다. 실제 읽거나 확인하지 않은 원문을 확인했다고 쓰지 않는다. 디자인 참고자료의 문구는 내용 근거로 사용하지 않는다.

발표 전 확인사항이 많으면 부록에서 `확인 대상 / 추가로 필요한 자료 / 본문에서의 처리`로 정리한다.

## 검수 루프

검수는 확인 도장을 찍는 작업이 아니라 결함을 찾는 과정이다. 발견한 항목을 수정하고 다시 검사한다.

### 내용 검수

- 제목과 Header가 올바르게 구분되는가?
- Header가 본문을 정확히 요약하며, Header만 읽어도 전체 논리가 이어지는가?
- 근거 없는 주장·수치·점수·순위가 없는가?
- 가정·미확정 항목이 필요한 위치에 표시되는가?
- 본문의 모든 주요 요소가 해당 Header를 뒷받침하는가?
- 템플릿 문구·불필요한 예시 슬라이드가 남아 있지 않은가?
- 스타일 수정 시 내용·노트·슬라이드 순서와 개수가 그대로인가?

### 구조·서식 검수

- 제목/Header/구분선/Footer의 좌표·크기·서식·내부 여백이 일관적인가?
- Pretendard와 Regular/Bold 체계가 한글·영문·테마에 일치하는가?
- 본문 시작 위치, 좌우 여백, 하단 한계를 지켰는가?
- 표·도식의 채움·선·셀 여백·정렬 기준이 일관적인가?
- Footer는 발표 전체 제목과 페이지 번호만 포함하며 번호가 실제 순서인가?
- 텍스트·표·주요 도식·차트를 직접 편집할 수 있는가?
- PPTX 재열기, ZIP 무결성, XML 파싱, 관계 참조가 정상인가?

`../scripts/validate_deck.py`는 이 중 일부만 자동 검사한다. 통과해도 내용의 정확성, 출처 신뢰성, 모든 OOXML 적합성, 텍스트 넘침·겹침이 검증된 것은 아니다.

### 시각 검수

실제 PowerPoint 또는 신뢰할 수 있는 렌더러를 사용할 수 있다면 모든 슬라이드를 이미지로 렌더링하고 글자 넘침, 잘림, 도형 겹침, 저대비, 과밀도, 줄바꿈, 폰트 대체를 확인한다. 문제가 있는 페이지를 수정하고 재렌더링한다.

폰트 폭 추정·좌표 검사·패키지 재열기를 실제 렌더링 검사라고 부르지 않는다. 렌더링 환경이 없거나 권한이 차단되면 그 한계를 알린다. 실제 시각 검수를 하지 않았다면 “잘림 없음”처럼 시각 결과를 단정하지 않는다.

## 전달

편집 가능한 PPTX를 제공한다. 주요 변경사항과 미확정 항목, 수행한 검수 및 수행하지 못한 검수만 간결하게 설명한다. 원본은 보존하며 별도 파일로 저장한다. 사용자가 요청하지 않은 HTML 보고서·설명 문서를 불필요하게 만들지 않는다.
