# PPTX 구현과 이식성

## 환경

이 스킬은 Codex/Claude Code/Claude의 표준 SKILL.md 리소스 로딩을 전제로 하되 전용 API를 요구하지 않는다. 현재 호스트의 파일·실행·네트워크·승인 정책을 따른다. 호스트에서 제공하는 PPTX 작업 스킬이 있으면 읽는다.

- PPTX 조작: python-pptx 등 검증된 OOXML 라이브러리를 사용할 수 있다.
- DOCX 내용: python-docx 또는 해당 호스트의 문서 도구로 문단·표·노트 등 관련 컨테이너를 확인한다.
- 구조 검수 스크립트는 Python 3.9+ 표준 라이브러리만 사용한다.
- 생성 라이브러리·글꼴·렌더러가 없으면 해당 환경의 설치 정책에 따라 필요한 의존성을 알린다. 설치/실행 성공을 가정하지 않는다.
- Pretendard 파일은 번들에 포함하지 않는다. 폰트 설정과 폰트 설치·임베딩은 별개의 작업이다.

## 템플릿 재사용

`../assets/consulting-template.pptx`는 네이티브 도형·표·텍스트를 사용하는 기본 양식과 일반적인 본문 예시다. 실제 원고·개인 정보·검증된 사실을 제공하는 파일이 아니다.

1. 템플릿을 복사해 새 산출물로 작업한다. 슬라이드 크기, 레이아웃, placeholder idx, 색상·폰트 상속을 먼저 검사한다.
2. 표지·내용용 공통 레이아웃을 사용한다. 새 본문은 메시지에 맞춰 생성한다. 예시 레이아웃에 억지로 모든 내용을 맞추지 않는다.
3. 본문 내용 슬라이드의 제목 idx=0, Header idx=1, 페이지 idx=12가 기본이다. 실제 객체를 검사한 뒤 이용한다.
4. 발표 전체 제목은 마스터의 공통 Footer 텍스트에서 한 번 교체한다. 기본 예시 문구는 `발표 전체 제목`이다.
5. 모든 예시 문구와 표·도식 항목을 실제 내용으로 교체한다. 필요 없는 예시 슬라이드는 삭제한다.
6. 실제 순서대로 페이지 필드 캐시 값을 갱신한다. 슬라이드 번호를 제목 번호와 혼동하지 않는다.
7. 내용이 확정된 후 각 슬라이드의 출처·상세 조건을 노트에 작성한다.

## 상속과 네이티브 요소

- title/Header placeholder의 개별 좌표·폰트 override를 최소화하고 공통 레이아웃에서 관리한다.
- 스크립트로 생성한 일반 텍스트 상자·표 셀에도 한글/영문용 실제 font family를 명시한다. theme major/minor 및 Hang 글꼴도 실제 사용값과 맞춘다.
- Pretendard Regular/Bold를 사용한다. 존재를 확인하지 않은 폰트 패밀리 이름이나 임의의 ExtraBold 이름을 설정하지 않는다.
- python-pptx의 슬라이드 생성은 번호 placeholder를 자동 복제하지 않을 수 있다. 레이아웃의 번호 placeholder를 확인하고 필요하면 네이티브 placeholder로 복제한다. 번호는 실제 순서의 `slidenum` 필드로 갱신한다.
- 노트의 슬라이드 번호 및 마스터 placeholder와 실제 본문 텍스트를 구분한다.
- 네이티브 표는 add_table, 차트는 데이터 워크북을 포함한 편집형 차트로 생성한다. 스크린샷으로 대체하지 않는다.
- 슬라이드 삭제·재정렬은 목록과 관계 ID를 함께 관리한다. 삭제한 원문·노트·개인 정보가 도달 가능한 패키지 파트에 남지 않았는지 확인한다.

## OOXML 주의사항

개체 모델로 처리할 수 없는 부분만 최소한으로 XML을 수정한다. 기존 관계와 파트는 보존한다.

- shape ID는 각 슬라이드/레이아웃/마스터 안에서 유일해야 한다. 다른 파트의 도형을 복제한 뒤 충돌을 확인한다.
- a:pPr는 문단 안에서 한 개만, 텍스트 run보다 앞에 있어야 한다.
- 기존 문단 clear()가 a:pPr를 남길 수 있다. 새 스타일을 추가하면서 중복 pPr를 만들지 않는다.
- 제목/Header에는 필요 시 buNone을 지정해 상속된 본문 bullet을 제거한다.
- 표 셀 경계선과 채움 등 자식 요소의 OOXML 순서를 유지한다.
- 상단 밴드의 gradient와 옅은 면은 네이티브 도형으로 유지한다. 템플릿에 없는 그림자나 입체효과가 theme에서 상속되지 않는지 확인한다.
- 압축 패키지에서 미디어 수만 확인해서 편집 가능성을 전부 검증했다고 주장하지 않는다. 실제 shape/table/chart 개체도 검사한다.

## 기본 검수 명령

이 파일의 경로가 아니라 스킬 폴더를 기준으로 실제 절대 경로를 해석해서 실행한다.

```text
python scripts/validate_deck.py /path/to/output.pptx
python scripts/validate_deck.py /path/to/output.pptx --json /path/to/qa.json
python scripts/validate_deck.py /path/to/output.pptx --structure-only
```

- 기본 모드는 번들 토큰의 좌표·Pretendard/색상 체계를 일부 확인한다.
- 사용자 지정 화면 비율·양식에는 structure-only를 사용하고 요청 규격을 별도 검수한다.
- errors가 있으면 수정하고 다시 검사한다. warnings도 검토하고 실제 의도와 일치하는지 확인한다.
- 결과는 구조 검사 범위만 의미한다. 텍스트 폭 추정과 실제 슬라이드 렌더링을 혼동하지 않는다.
- 템플릿 자체를 검사하면 의도적인 예시 문구 경고가 나올 수 있다. 실제 산출물에는 그런 문구를 남기지 않는다.

## 공유 범위

스킬 폴더는 SKILL.md, references, assets, scripts를 함께 이동해야 한다. 설치 위치가 달라도 내부 파일의 상대 경로는 유지한다. 이 스킬은 Codex의 전용 YAML이나 Claude 전용 frontmatter 없이 name/description만으로 발견될 수 있게 작성됐다. 실제 앱에서 스킬이 로딩됐는지는 해당 앱에서 별도로 확인한다.
